# 第 3 章 · 看懂仓库页面

打开任何一个仓库（比如 [vuejs/vue](https://github.com/vuejs/vue)），满屏的东西确实劝退。这一章带你把每个角落都认一遍。以后再打开任何仓库，你会发现**所有仓库长得都一样**——这就是 GitHub 的妙处，学会一次，到处通用。

## 页面骨架图

```
┌─────────────────────────────────────────────────┐
│  用户名 / 仓库名          Watch  Fork  Star      │
├─────────────────────────────────────────────────┤
│  [Code] [Issues] [Pull requests] [Actions] ...  │  ← 仓库功能标签页
├─────────────────────────────────────────────────┤
│  main ▾    分支数    标签(Tags)                   │  ← 分支和版本
├─────────────────────────────────────────────────┤
│  README 渲染内容（仓库的门面）                     │
├─────────────────────────────────────────────────┤
│  文件和文件夹列表  ▸ 最后一次提交说明 ▸ 时间       │
└─────────────────────────────────────────────────┘
```

## 右上角三个数字按钮：Watch / Fork / Star

这是仓库的「社交三件套」：

| 按钮 | 意思 | 什么时候用 |
|------|------|-----------|
| **Watch** | 关注。仓库有任何动静（新 Issue、新提交）都通知你 | 你深度参与这个项目时 |
| **Fork** | 复制一份到**你自己账号**下 | 你想改这个项目的代码时 |
| **Star** | 点赞 + 收藏夹 | 你觉得这个项目好用，Star 数就是项目的热度 |

新手常见误区：**Star 不会让代码出现在你账号下**，它只是个赞。想拥有副本要用 Fork。

## 中间一排标签页：仓库的功能区

- **Code**：代码本体的展示页，你最常待的地方
- **Issues**：提问和 bug 报告区。发现项目有问题、有疑问，来这里发帖（开源项目用它当论坛用）
- **Pull requests**：别人提议修改代码的审核区。想给项目贡献代码，先在这里提 PR 等作者审核
- **Actions**：自动化流水线（自动测试、自动发布），新手初期用不到
- **Wiki**：项目的补充文档
- **Security / Insights / Settings**（Settings 只有你自己的仓库才有）：安全报告、数据统计、仓库设置

## 文件列表区域

- 每一行是一个文件或文件夹，右侧灰色小字是**最后一次提交的说明**和**时间**——点它能看这次改了什么
- 文件名旁边如果有彩色小徽章（比如 `MIT license`），是开源协议
- 想知道某个文件是谁在什么时候改的：打开文件后点右上角 **History**

## 文件列表里那一堆东西，分别是什么

点开一个成熟项目的根目录，大概长这样（以 Vue 3 核心仓库为例）：

```
.github/          chore: update issue form [ci skip]        3年前
benchmarks/       chore(benchmarks:ssr): createRenderer...   4年前
packages/         chore: fix link broken (#13192)            2年前
src/              fix(lifecycle): ensure component effect...  3年前
test/             fix(watch): new property addition should... 3年前
types/            fix(types): export more types for v3...     3年前
.editorconfig     chore: https link to editorconfig.org       6年前
.gitignore        workflow: fix release check + remove dist   4年前
.prettierrc       workflow: remove eslint, apply prettier     4年前
CHANGELOG.md      chore: fix spelling mistakes (#13216)       2年前
LICENSE           use present for copyright range            10年前
README.md         chore: browser compatibility table link      2年前
package.json      chore: avoid generating unused dts          4年前
```

**别慌，这些都是行业约定，换 90% 的仓库都叫这个名字。** 认识一次，到处通用。

### 文件夹

| 名字 | 是什么 | 你要不要看 |
|------|--------|-----------|
| `src` | source 源码本体 | **要看**，这是作者真正写的代码 |
| `packages` | 一个仓库里装多个独立包（monorepo），每个子目录能单独发布 | 想深挖就看 |
| `dist` | 打包编译后的产物，代码被压缩成一坨 | **别看**，也不要手改 |
| `test` / `tests` | 单元测试代码 | 想知道某功能怎么用，看测试最快 |
| `examples` | 官方示例，一般都是能直接运行的 demo | **新手优先看这个** |
| `docs` | 文档源码 | 找用法看这里 |
| `types` | TypeScript 类型声明，给编辑器代码补全用 | 写 TS 时才看 |
| `scripts` | 构建、发布用的自动化脚本 | 不用看 |
| `benchmarks` | 性能基准测试，比较不同实现快多少 | 不用看 |
| `compiler-sfc` | 特定功能的子模块（这里是 Vue 单文件组件编译器） | 按需 |
| `.github` | **和代码无关**。放 Actions 自动化流程、Issue 模板、PR 模板、CODEOWNERS | 想提 Issue 前可以瞄一眼模板 |

以点开头的文件夹和文件是**隐藏文件**，在 macOS / Linux 上默认不显示，它们是给工具和平台读的配置，不是给人读的代码。

### 通用配置文件

| 文件名 | 干什么的 |
|--------|---------|
| `.gitignore` | 声明哪些文件**不**纳入版本管理。通常是 `node_modules`、`dist`、`.env`（存密码的） |
| `.editorconfig` | 统一缩进、换行符、字符编码，免得张三用 2 空格李四用 Tab，一提交全是大红大绿 |
| `.prettierrc` | 代码格式化规则（缩进几格、用不用单引号、每行多宽） |
| `.eslintrc` | 代码检查规则，管的是逻辑层面的写法问题 |
| `.git-blame-ignore-revs` | 让 `git blame` 忽略「全项目跑了一次格式化」这类噪音提交，查代码作者时不被误导 |
| `package.json` | **项目身份证**：名字、版本、依赖、可执行命令（`npm run build` 跑的就是这里面定义的） |
| `package-lock.json` / `pnpm-lock.yaml` | 锁死每个依赖的精确版本，保证所有人装出来的环境一模一样 |
| `tsconfig.json` | TypeScript 编译配置 |
| `vite.config.ts` / `rollup.config.js` | 打包工具配置 |
| `api-extractor.json` | 从 TS 类型里提取、整理对外 API 文档 |
| `LICENSE` | 开源协议，决定你能拿这份代码做什么 |
| `README.md` | 门面，项目说明 |
| `CHANGELOG.md` | 版本变更记录，**升级前必看**，能提前知道哪个功能被删了 |
| `CONTRIBUTING.md` | 参与贡献的规矩，提 PR 前读一遍 |
| `BACKERS.md` / `SPONSORS.md` | 赞助者鸣谢名单，纯展示 |

### 右边那两列是什么

- 中间那段文字是**最后一次提交的说明**。`chore:` `feat:` `fix:` `docs:` 这些前缀是行业通用的提交分类：`feat` 加功能、`fix` 修 bug、`chore` 杂活、`docs` 改文档
- 最右边「3年前」是这个文件**最后一次被修改**的时间。一堆文件都停在三四年前，说明项目可能不太活跃了，下载前留意一下

### 这些东西跟你有什么关系

按你的目的分三档，别一上来全看：

1. **只想用这个软件** → 只看 `README`、右侧 `Releases`、`LICENSE`，其他全部忽略
2. **想学它是怎么写的** → `examples` 跑起来看效果，再去 `src` 读实现
3. **想贡献代码** → 读 `CONTRIBUTING.md`，看 `.github` 里的 Issue/PR 模板，跑一遍 `test`



README 是仓库首页自动展示的说明文档，**评判一个项目好不好，先看 README 写没写清楚**：

- 好的 README：项目是干嘛的、怎么安装、怎么使用、有没有截图
- 看到只有一个光秃秃的仓库名、README 都没有的，谨慎使用

## 分支（Branch）是什么？

左上角的 `main` 是**分支名**。可以理解为：主分支是「正式版」，其他分支是「草稿版」，草稿改好了再合并回正式版。你 clone 和浏览时默认都在 `main` 上，新手阶段知道这个就够。

## Release：官方成品下载

仓库首页右侧栏有 **Releases** 区域，这里放作者**打包装好的成品**（exe、zip 等）。

重要区别：
- 想直接**用**这个软件 → 去 Releases 下载成品
- 想看/改**源代码** → 在 Code 页面操作
