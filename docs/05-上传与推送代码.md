# 第 5 章 · 上传与推送代码

这一章带你走通最核心的闭环：**把本地代码推送到 GitHub**。跟着敲一遍，比看十篇教程都管用。

## 核心流程图

```
本地修改 → git add（打包）→ git commit（写说明）→ git push（上传）
                                              ↘ git pull（拉取别人的更新）
```

## 第一步：在 GitHub 上建一个空仓库

1. 登录 GitHub，点右上角 **+** → **New repository**
2. 填仓库名（英文、短横线分隔，如 `my-first-repo`）
3. 勾选 **Public**（公开，任何人可见；Private 则只有你能看）
4. 勾选 **Add a README file**（省得仓库空荡荡）
5. 点 **Create repository**

## 第二步：本地初始化并推送

在电脑上新建一个文件夹，打开终端（Windows 用 Git Bash），依次执行：

```bash
# 1. 进入你的项目文件夹
cd D:/projects/my-first-repo

# 2. 让 Git 接管这个文件夹（生成 .git 隐藏目录）
git init

# 3. 随便放个文件进去测试，比如写个 hello.txt

# 4. 把文件放进"待提交区"（. 代表当前文件夹全部内容）
git add .

# 5. 提交，写一句说明这次改了什么
git commit -m "第一次提交"

# 6. 告诉 Git 远端仓库在哪（换成你的地址）
git remote add origin https://github.com/你的用户名/my-first-repo.git

# 7. 上传！
git push -u origin main
```

push 时会弹出登录窗口，登录你的 GitHub 账号授权即可。看到 `Branch 'main' set up to track...` 就成功了。刷新 GitHub 页面，你的文件已经在上面了。

## 日常更新三连

以后每次改了代码，只需三步：

```bash
git add .
git commit -m "描述这次改了什么"
git push
```

`-u origin main` 只在第一次需要，之后直接 `git push`。

## 写 commit 说明的三个原则

commit 说明是给未来的自己（和别人）看的：

1. **写改了什么**，不写"改了一下" `"update"` `"123"` 都是差说明
2. **一句话说清楚**：`修复登录页在手机上错位的 bug`
3. **小步提交**：一次 commit 只做一件事，别把一周的改动攒一起

## clone 别人仓库后想改？走 Fork 流程

直接 clone 别人的仓库，你没有 push 权限。正确姿势：

1. 在对方仓库页面点 **Fork**（副本进入你的账号）
2. clone **你自己的** fork 仓库到本地
3. 改完 push 到你的 fork
4. 在 GitHub 上点 **Contribute → Open pull request**，向原作者提议合并

作者审核通过后，你的代码就进入原项目了——这就是「开源贡献」，走到这一步你已经超过大多数新手了。
